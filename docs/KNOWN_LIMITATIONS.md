# Known limitations

- **TinyFish coverage is bounded.** A live central `AUG-2026` run stored ten records and is present in PostgreSQL. All ten were independently compared with the official CDSCO public table on 18 October; there were no substantive field mismatches, and two manufacturer strings differed only in whitespace. This verifies the saved slice, not full CDSCO coverage. No additional TinyFish request was made.
- **ContextOS live browser acceptance remains open.** A live Sarvam response for the selected `VRNT-933` CDSCO alert passed the ContextOS handler, returned `sarvam` mode, and persisted a `success` audit. A synthetic browser journey passed, but a signed-in page submission to the real handler was not completed. Earlier failed-safe calls remain in the audit history; their raw generated text was not retained.
- **No live Sarvam OCR or translation acceptance.** Their adapters passed mocked schema and error checks, but real image extraction and translated wording require separate approved requests.
- **No real camera acceptance.** Generated QR and EAN-13 fixtures decode in automated tests, but the camera has not been tried on a physical phone or printed code. Automated scan workflow uses a mocked OCR API and manual batch correction.
- **Limited Hindi coverage.** Navigation, auth, password recovery, dashboard and key scan/ContextOS surfaces switch to Hindi and the preference survives refresh. Older forms and detail, supplier and settings pages still contain English. Sarvam Hindi generation and translation remain unverified live.
- **No live two-user browser acceptance.** The user reports one successful Supabase signup, pharmacy onboarding, and inventory upload. Backend tests prove pharmacy scoping and PostgreSQL isolation; Playwright uses synthetic Auth/API responses. A second confirmed Supabase user is needed for manual cross-account acceptance.
- **Custom SMTP is not configured or tested.** The app now gives useful email throttling guidance and supports reset-password callbacks. The user must verify a sending domain, configure Supabase SMTP and allowlisted redirects, then confirm real mail delivery. See [email setup](SUPABASE_EMAIL_SETUP.md).
- **No Docker runtime validation.** `docker` is installed but Docker Desktop's Linux engine is unavailable. Local API/web commands and Compose configuration are documented.
- **Basic private file attachments only.** Investigation evidence files up to 2 MB are stored in PostgreSQL with tenant checks. Images are decoded and PDFs receive basic framing checks, but this does not constitute malware scanning or complete PDF structural validation. Antivirus scanning and object storage are not implemented. QR/OCR uploads are processed transiently and are not automatically saved as evidence.
- **Source URL points to the CDSCO NSQ table.** The public site has no stable per-row URL in retrieved data. Reviewers must filter by period and batch.
- **Coverage is intentionally bounded.** One operator command covers one period and up to 25 rows; no national archive pagination, deletion detection or automatic scheduling. Freshness reflects successful runs, not full current coverage.
- **Matching and AI remain decision support.** Name/manufacturer comparison is conservative; batch equality is deterministic. OCR can misread print. A potential match is not physical confirmation; no match is not proof of safety. ContextOS can fall back when generated text fails checks, but not every LLM claim can be mechanically proven.
- **Schema migration management remains.** Startup creates missing tables and applies RLS/grants. A versioned migration and backup process is needed before changing existing PostgreSQL columns in production. A legacy encrypted BYOK table remains retained but inaccessible through current APIs.
- **Production operations remain.** HTTPS, exact CORS origins, monitored backups, secret rotation, provider spend controls, and live deployment checks must precede public launch.
- **Provider spend is limited per pharmacy, not account-wide.** ContextOS, OCR, and translation have daily per-pharmacy request caps, and TinyFish sync is operator-only and limited to one period and 25 rows. A global Sarvam budget and billing alert are still needed before open registration.
